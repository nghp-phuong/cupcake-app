Giao diện trước / sau khi làm lại

Toàn bộ giao diện chuyển từ kiểu app phẳng (gradient, viền thẳng, icon Material, gợn sóng khi chạm) sang phong cách vẽ tay: giấy, gỗ, vải, viền nâu run tay, màu nước loang. Logic, dữ liệu, lưu game và luồng màn hình không đổi.

Bộ design system và bàn giao

Bộ thành phần SL*

Ở lib/ui/sugarleaf/: SLButton (primary, secondary, icon), SLPanel, SLPaperCard, SLOrderTicket, SLChip, SLBadge, SLStamp, SLSpeechBubble, SLNameTag, SLTopBar, SLDialog, SLTabBar, SLProgressBar, SLToggle, SLIcon, SLArtIcon, SLToast, SLTooltip, SLRule, SLLoadingDots. Xem đủ trạng thái trong UI Gallery (Cài đặt → UI Gallery, chỉ có ở bản debug).

Vì sao vẽ bằng CustomPainter, không dùng nine-patch

  • Đổi màu theo trạng thái (đã nhận, đang chọn, khoá, VIP) chỉ bằng tham số.
  • Co giãn mọi kích thước mà nét run tay không bị kéo méo; luôn sắc ở mọi mật độ màn hình.
  • Không thêm ảnh; hình viền ra giống nhau mỗi lần nhờ seed cố định.
  • Hình đã dựng được lưu lại (LRU 128 mục): vẽ lại ~0,02 ms/hình, 60 hình ~1,5 ms/khung.

Ảnh cần vẽ thêm

58 icon nét tay đang vẽ bằng code. Prompt Gemini (màu nước, viền nâu, tách nền trắng thành trong suốt), tạo theo tờ 3×3: icon-prompts.md. Có ảnh rồi chỉ cần chép vào assets/art/icons/, app tự dùng ảnh thay hình code.

Trải nghiệm bản web

Bản build ở build/web. Chạy flutter build web --release rồi mở bằng một máy chủ tĩnh (dự án dùng cổng 8791). Xoay ngang hoặc dùng cửa sổ 16:9.

Ảnh "trước" chụp ở Bước 1 (docs/design/ui-before/), lúc các màn còn vẽ bánh, lò, nền bằng hình code. Ảnh "sau · như app thật" (ui-after/) có đủ ảnh vẽ tay như khi chơi; ảnh "sau · cùng điều kiện" (ui-after-codeart/) tắt ảnh đồ hoạ để chỉ so phần giao diện. Chụp bằng tool/screens/render_screens_test.dart ở khung 1280×720, dữ liệu giả lập; ảnh cài đặt có thêm nút "UI Gallery (debug)" vì công cụ chạy ở chế độ debug. Ở vài màn quầy, khách bên "trước" và "sau" khác nhau vì công cụ tự chọn lại ngày có đủ ảnh nhân vật sau khi hai nhân vật được vẽ lại.
